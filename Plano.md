Plano de Desenvolvimento: Proxy NIM Load BalancerVisão Geral da ArquiteturaO sistema atua como um intermediário local para contornar limites de 40 RPM da API da NVIDIA NIM. Ele intercepta as chamadas dos seus agentes, injeta a chave de API correta baseada no remetente e gerencia falhas (HTTP 429 Too Many Requests) roteando para chaves secundárias.1. Portas e ServiçosPorta 88 (Painel Admin): Servidor estático e API REST para gerenciamento de chaves em tempo real. Não exige reinicialização do container para adicionar novas keys.Porta 11431 (Proxy API): Endpoint principal que receberá as requisições dos seus agentes de IA.2. A Lógica de Roteamento (Pipeline de Chaves)Cada requisição passa por um filtro baseado no Header customizado (x-agent-type):Header x-agent-type: main: Tenta primeiro as chaves cadastradas com papel "Principal". Se falhar, faz fallback para as chaves "Sub" ou "Geral".Header x-agent-type: sub: Faz um rodízio (Round-Robin) entre as chaves cadastradas com papel "Sub". Se falhar, tenta o fallback.Sem Header (Balanceamento puro): Se nenhum header for enviado, o proxy faz Round-Robin em todas as chaves disponíveis.3. Tratamento de Streaming (SSE)APIs de LLM costumam utilizar o parâmetro "stream": true. O proxy foi desenhado utilizando a API nativa de Web Streams do Node.js (Readable.fromWeb), garantindo que os tokens sejam enviados para o seu agente em tempo real, sem buffering.Passos para ExecuçãoColoque todos os arquivos gerados no mesmo diretório.Abra o terminal nessa pasta.Execute o comando para subir a infraestrutura:docker-compose up -d --build

Acesse http://localhost:88 no seu navegador para cadastrar as 3 chaves fornecidas pela NVIDIA. Atribua o papel "Principal" para uma e "Sub" para as outras duas.Configure o Claude Code / LangChain / AutoGen para apontar a Base URL para http://localhost:11431/v1 e inclua o header x-agent-type: main ou sub dependendo do worker.
